# Instructions for coding agents

This repository holds the offline map packages for Blackout Maps and the tools that build and check them. The apps (web, Android, iOS) are in [bug-catcher90/blackout-maps](https://github.com/bug-catcher90/blackout-maps) and load whatever `catalog/index.json` here lists. Read [SPEC.md](SPEC.md) before changing anything under `catalog/` or `scripts/`.

## Never

- Never hand-edit `catalog/<id>/` parts, part sizes or SHA-256s. They are generated by `scripts/maps/make-catalog.mjs`.
- Never hand-edit `catalog/index.json`. Run `node scripts/make-index.mjs`.
- Never commit a package that fails `node scripts/validate-catalog.mjs catalog/<id>.json`.
- Never keep old parts next to new ones, or commit anything other than map data and tooling to `catalog/`.
- Never commit a file over 45,000,000 bytes or push more than about 1.5 GB at once (GitHub rejects 2 GB pushes). Push one package, or one country's regions, per commit.
- Never clone the whole repository unless you need every package; it is about 12 GB. Use a partial, sparse clone (below).
- Never change the binary formats here. They are defined by the app repository's readers; `scripts/readers/` is a copy refreshed by `scripts/sync-readers.sh`.

## Layout

```
catalog/index.json          generated; every entry; what the apps read
catalog/<id>.json           generated entry for one package
catalog/<id>/               generated parts: map.pmtiles*, roads.bin.gz*, buildings.bin.gz*,
                            places.bin.gz, water.bin.gz, addresses.bin.gz, geo.json.gz
scripts/maps/countries.json hand-edited: one entry per package (id, name, flag, geofabrik, region, country)
scripts/maps/regions/       region polygons (make-regions.py writes them)
scripts/maps/build-country.sh   the extraction pipeline for one package
scripts/validate-catalog.mjs    the validator; CI runs it
scripts/make-index.mjs          writes or checks catalog/index.json
scripts/serve-local.mjs         serves this checkout to a localhost web app
scripts/readers/                copies of the apps' readers (do not edit)
```

## Required layers and limits

Every package has seven assets, keys `map`, `roads`, `buildings`, `places`, `water`, `addresses`, `geo`: basemap, roads, buildings, places/POIs, water, addresses and search. CI rejects a package missing any of them, including `portugal` (autoload).

- Parts: at most 45,000,000 bytes each, named `<file>.gz` for one part or `<file>.gz.000`, `.001`, … for several; `map.pmtiles` is not gzipped.
- Memory: `roads.bytes + buildings.bytes` (unpacked) under 450,000,000. Over that, split the country into regions with `scripts/maps/make-regions.py`.
- Part URLs: `https://raw.githubusercontent.com/bug-catcher90/blackout-maps-data/main/catalog/<id>/<part>`.

## Setup

```bash
git clone --filter=blob:none --sparse https://github.com/bug-catcher90/blackout-maps-data
cd blackout-maps-data
git sparse-checkout set --no-cone '/*' '!/catalog/*/'          # code and entries only
git sparse-checkout add '/catalog/<id>/'                         # plus the packages you touch
```

Tools for building: `osmium-tool` ≥ 1.14, `pmtiles` (go-pmtiles) ≥ 1.20, Node ≥ 20, `pigz`, `curl`; `python3` with `shapely` for regions. On Debian/Ubuntu: `apt-get install osmium-tool pigz curl python3-shapely`, and the `pmtiles` binary from github.com/protomaps/go-pmtiles/releases. Building needs about 10 GB of disk and 8 GB of memory per package; set `NODE_HEAP_MB` lower on small machines.

## Tasks

**Add or rebuild a package**

1. Add or edit the entry in `scripts/maps/countries.json` (see CONTRIBUTING.md). For a country whose extract is over about 420 MB, add `"split": { "fromLevel": 4 }` and run `python3 scripts/maps/make-regions.py <country> <extract.osm.pbf>`, then build each region id.
2. `scripts/maps/build-country.sh <id> /tmp/blackout-maps`. It writes `catalog/<id>/`, `catalog/<id>.json`, refreshes `catalog/index.json` and runs the validator.
3. `node scripts/validate-catalog.mjs catalog/<id>.json` must print `ok   <id>: 7/7 files opened`.
4. `node scripts/validate-catalog.mjs --shallow` must print no `FAIL`.
5. Commit `scripts/maps/countries.json`, `scripts/maps/regions/…` (if any), `catalog/<id>.json`, `catalog/<id>/` and `catalog/index.json`.

**Change a script:** run `node scripts/validate-catalog.mjs --shallow` and a full check of a small package (`catalog/northern-ireland.json`).

**A format changed in the app repository:** `scripts/sync-readers.sh <commit>`, rebuild the affected packages, validate, commit `scripts/readers/` with the packages.

**Resolve a conflict in `catalog/index.json`:** take either side, run `node scripts/make-index.mjs`, commit.

## Checks

| Command | What it checks | Time |
| --- | --- | --- |
| `node scripts/validate-catalog.mjs --shallow` | every entry's fields, required layers, sizes, URL shape, memory budget, and the index | seconds |
| `node scripts/validate-catalog.mjs catalog/<id>.json` | the above, plus every part's size and SHA-256 and opening every file with the apps' readers | seconds to a minute |
| `node scripts/validate-catalog.mjs --remote` | every part URL answers with its size and `Access-Control-Allow-Origin: *` | minutes |
| `node scripts/make-index.mjs --check` | the index alone | instant |

CI (`.github/workflows/validate-catalog.yml`) runs the shallow check plus a full check of changed packages on every pull request and push to `main`, and the remote check weekly.
